# getVehicleManagerLimits

Reads a multi vehicle's auto-fulfill threshold, withdrawal buffer and deposit cap in one multicall.

- [`buildSetThresholdsCall`](/actions/buildSetThresholdsCall) replaces both thresholds at once.

## Import

```ts twoslash
import { getVehicleManagerLimits } from '@railnetorg/railnet-sdk'
```

## Usage

```ts
import { createPublicClient, http } from 'viem'
import { mainnet } from 'viem/chains'
import { getVehicleManagerLimits } from '@railnetorg/railnet-sdk'

const client = createPublicClient({ chain: mainnet, transport: http() })

const limits = await getVehicleManagerLimits(client, { vehicleManager })
```

## Returns

`VehicleManagerLimits`

```ts
type VehicleManagerLimits = {
  minSharesForAutoFulfill: bigint
  extraAssetsForWithdrawalRequests: bigint
  maxTotalAssets: bigint
}
```

### minSharesForAutoFulfill

Unredeemable shares needed to trigger auto-fulfill on deposits, in **vehicle shares** (18 decimals).
`2n ** 256n - 1n` disables auto-fulfill, and is the value a fresh deployment starts from.

### extraAssetsForWithdrawalRequests

Buffer added on top of a requested redeem, in the multi vehicle's asset units. Capped on write at
`type(uint128).max`.

### maxTotalAssets

Hard cap on `totalAssets()`, enforced at deposit time, in asset units. `2n ** 256n - 1n` means
uncapped. See [`buildSetMaxTotalAssetsCall`](/actions/buildSetMaxTotalAssetsCall) for what counts
against it.

## Parameters

### vehicleManager

- **Type:** `Address`

The multi vehicle's VehicleManager.
