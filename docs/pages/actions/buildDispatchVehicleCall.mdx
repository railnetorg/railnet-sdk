# buildDispatchVehicleCall

Builds the `sectorAccountingEngine.dispatch()` call, a deposit or a redeem between a
[sector](/types/Sector) and a sub-vehicle.

- Requires `MULTI_VEHICLE_DISPATCH` scoped to the SectorAccountingEngine.
- On an async vehicle the query stays short of settlement after the transaction, and the funds
  with it. `simulateDispatchVehicle` tells which case applies before a second leg depends on it.
- Reallocating between two vehicles is a redeem dispatch followed by a deposit dispatch. See
  [Rebalancing between vehicles](/guides/rebalancingBetweenVehicles).

## Import

```ts twoslash
import { buildDispatchVehicleCall, simulateDispatchVehicle } from '@railnetorg/railnet-sdk'
```

## Usage

```ts
import { simulateContract, writeContract } from 'viem/actions'
import { buildDispatchVehicleCall } from '@railnetorg/railnet-sdk'

const { request } = await simulateContract(client, {
  ...buildDispatchVehicleCall({
    sectorAccountingEngine: '0x...',
    vehicle: aaveV3Vehicle,
    mode: QueryMode.REDEEM,
    amount: 1000000n,
    settledDestination: SECTOR_AVAILABLE,
    rejectedDestination: vehicleSector(aaveV3Vehicle),
    operationId: '0x...',
  }),
  account: '0xd2135CfB216b74109775236E36d4b433F1DF507B',
})

const hash = await writeContract(client, request)
```

Checking whether it will settle in one transaction:

```ts
import { QueryState, simulateDispatchVehicle } from '@railnetorg/railnet-sdk'

const { query, state } = await simulateDispatchVehicle(walletClient, {
  /* same parameters, plus account */
})

if (state !== QueryState.SETTLED && state !== QueryState.REJECTED) {
  // async vehicle: keep `query` to progress it once the vehicle settles
}
```

## Returns

A prepared call: `{ address, abi, functionName, args }`.

## Parameters

### sectorAccountingEngine

- **Type:** `Address`

The SectorAccountingEngine of the MultiVehicle.

### vehicle

- **Type:** `Address`

The sub-vehicle to deposit into or redeem from. A deposit requires an authorized vehicle. A redeem
does not, so a funded vehicle can be unwound after `unauthorize`.

### mode

- **Type:** `QueryMode`

`QueryMode.DEPOSIT` to allocate into the vehicle, `QueryMode.REDEEM` to pull out of it.

### amount

- **Type:** `bigint`

The amount to dispatch, or `maxUint256` for the entire sector balance. With `maxUint256`, a binding
cap or vehicle limit reduces the amount. With an explicit amount it reverts.

### settledDestination / rejectedDestination

- **Type:** [`Sector`](/types/Sector)

Where the output lands when the query settles, and where it lands when it is rejected. A redeem
typically settles into `SECTOR_AVAILABLE` and falls back to the vehicle's own sector.

### minOutput (optional)

- **Type:** `bigint`
- **Default:** `0n`

Slippage floor on the vehicle's output. The builder throws on `minOutput` with `amount: maxUint256`,
and the engine reverts that combination with `MinOutputRequiresPinnedAmount`.

### data (optional)

- **Type:** `Hex`
- **Default:** `'0x'`

Vehicle-specific payload forwarded to the STEAM call.

### operationId

- **Type:** `Hex`

A caller-supplied identifier echoed in the `Dispatched`, `DispatchSkipped` and `Limited*` events.

## simulateDispatchVehicle

```ts
const { query, state } = await simulateDispatchVehicle(client, {
  /* same parameters, plus account */
})
```

Takes the builder's parameters and an `account`, sends nothing, and returns the
[`Query`](/types/Query) the dispatch would create with the
[`QueryState`](/types/Enums#querystate) it would reach. `SETTLED`
and `REJECTED` are terminal. On any other state keep `query`,
[`buildProgressQueryCall`](/actions/buildProgressQueryCall) takes the exact struct.
