# buildWrapQueryCall

Mints an ERC-721 over a live query, so the claim on its proceeds becomes transferable. Returns the `tokenId`.

The OwnerRegistry records who owns a conduit's live queries; wrapping turns that record into a token
someone else can buy or receive.

## Import

```ts
import { buildWrapQueryCall, getQueryClaim } from '@railnetorg/railnet-sdk'
```

## Usage

```ts
import { simulateContract, writeContract } from 'viem/actions'
import { buildWrapQueryCall } from '@railnetorg/railnet-sdk'

const { request } = await simulateContract(client, {
  ...buildWrapQueryCall({ ownerRegistry, query, conduit }),
  account,
})

await writeContract(client, request)
```

## Preconditions

The caller must be the query's registered owner (`QueryNotRegistered`, `UnauthorizedWrap`), the
query must not be wrapped already (`QueryAlreadyWrapped`) and must still be live —
`NonWrappableState` on `EMPTY`, `SETTLED` or `REJECTED`, since a finalized query has no claim left
to sell.

The conduit must also let the caller transfer to itself (`TransferNotAllowed`): a wrapped query is
a transferable claim, so it faces the same screen a transfer does. Check it first with
[`getTransferability`](/actions/getTransferability):

```ts
const canWrap = await getTransferability(client, { conduit, from: owner, to: owner })
```

## Returns

A prepared call: `{ address, abi, functionName, args }`. On chain it returns the minted `tokenId`.

## Parameters

### ownerRegistry

- **Type:** `Address`

The registry the conduit was spawned with. Fixed at spawn, with no setter.

### query

- **Type:** [`Query`](/utilities/queryIdentity)

The query to wrap, exactly as the conduit created it.

### conduit

- **Type:** `Address`

The conduit that owns the query. The registry namespaces every record by it, so the same query id
under two conduits is two records.

## getQueryClaim

```ts
const claim = await getQueryClaim(publicClient, { ownerRegistry, conduit, queryId })
// { owner, isWrapped, tokenId }
```

Who holds the claim, and whether it has been wrapped yet.

`wrap` clears `owner` and sets `tokenId`, so a zero `owner` means two opposite things: with
`isWrapped` true the NFT holder owns the claim, with it false the registry never knew this query.
Reading all three in one multicall is what makes them distinguishable.

## No unwrap builder

`unwrap` is keyed on `msg.sender` as the conduit namespace, so only the owning conduit can reach it,
and it does so at finalization — burning the spent claim before it can be transferred again. A
builder for it would be surface no integrator can call.
