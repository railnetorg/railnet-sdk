# getDepositConduitCall

Reads what a deposit needs — the conduit's vehicle — and returns the call along with the identity of
the query it will create. It only reads: sending the call is yours.

The `queryId` it returns is the value the conduit's `QueryCreated` event carries, so it is the key
that joins a transaction to an indexed query. It is known **before** the transaction is sent, so a
UI can show a pending query the moment the wallet confirms.

## Import

```ts
import { getDepositConduitCall, randomSalt } from '@railnetorg/railnet-sdk'
```

## Usage

```ts
import { simulateContract, writeContract } from 'viem/actions'
import { getDepositConduitCall, randomSalt } from '@railnetorg/railnet-sdk'

const { call, queryId } = await getDepositConduitCall(publicClient, {
  conduit: '0xA0Cf798816D4b9b9866b5330EEa46a18382f251e',
  token: '0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913',
  amount: 1_000_000n,
  sender: account.address,
  salt: randomSalt(),
})

const { request } = await simulateContract(publicClient, { ...call, account })
const hash = await writeContract(walletClient, request)

// `queryId` keys the query in your indexer, from here on
```

## Returns

```ts
type GetDepositConduitCallReturnType = {
  call: { address: Address; abi: Abi; functionName: string; args: readonly unknown[] }
  query: Query
  queryId: Hex
  vehicle: Address
}
```

## Parameters

Everything [`buildDepositConduitCall`](/actions/buildDepositConduitCall) takes, with `vehicle`
optional: it is read from `conduit.getVehicle()` when omitted.

`salt` stays required. It fixes the query's identity, so generating one behind your back would mean
the id you get back is not the one a retry sends.

## Why a redeem has no id

A deposit's query is built off chain, so its id is a pure function of what you built. A redeem's is
assembled by the conduit at the share ratio of the including block, so it cannot be known in
advance — [`getRedeemConduitCall`](/actions/getRedeemConduitCall) returns the query salt instead,
and [`extractQueryIds`](/utilities/receiptHelpers) reads the id back from the receipt.
