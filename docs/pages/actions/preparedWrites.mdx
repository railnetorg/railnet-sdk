# prepare* (Prepared Writes)

Every write is a `prepare*` builder. They are synchronous, take no client, and send nothing — they
return the contract call, so you decide when and how it goes out: simulate it, batch it, put it
behind a permit, or feed it to an app-side step engine.

The React hooks build on the same builders, so both paths encode the same call.

## Import

```ts
import { prepareSpawnConduit, randomSalt } from '@railnetorg/railnet-sdk'
```

## Usage

```ts
import { createWalletClient, http } from 'viem'
import { base } from 'viem/chains'
import { prepareSpawnConduit, randomSalt } from '@railnetorg/railnet-sdk'

const walletClient = createWalletClient({
  chain: base,
  transport: http(),
})

const prepared = prepareSpawnConduit({
  factory: '0x...',
  name: 'My Conduit',
  symbol: 'COND',
  vehicle: '0x...',
  initialExpectedSupply: 1000000n,
  transferEnabled: true,
  accessControl: '0x...',
  feeManager: '0x...',
  accountList: '0x...',
  ownerRegistry: '0x...',
  querySalt: randomSalt(),
  deploymentSalt: randomSalt(),
})

const hash = await walletClient.writeContract({
  ...prepared,
  account: '0xd2135CfB216b74109775236E36d4b433F1DF507B',
})
```

## Returns

`PreparedWrite`

```ts
type PreparedWrite = {
  address: Address
  abi: Abi
  functionName: string
  args: readonly unknown[]
}
```

Spread it into viem's `writeContract`, `simulateContract`, or `encodeFunctionData`. The actual
return type is narrower than `PreparedWrite` (the ABI and args stay literal), so viem keeps full
type inference when you spread it.

## Available builders

| Builder | Call |
| --- | --- |
| `prepareGrantScopedRole` | `externalAccessControl.grantScopedRole()` |
| `prepareRevokeScopedRole` | `externalAccessControl.revokeScopedRole()` |
| `prepareSetScopedRolePublic` | `externalAccessControl.setScopedRolePublic()` |
| `prepareSpawnAccessControl` | `accessControlFactory.spawn()` |
| `prepareSpawnConduit` | `conduitFactory.spawn()` |
| `prepareEnableConduit` | `conduit.enable()` |
| `prepareFinalizeConduitDeposit` | `conduitFactory.finalizeConduitDeposit()` |
| `prepareProcessConduitQuery` | `conduit.process()` |
| `prepareDepositConduit` | `conduit.create()` |
| `prepareRedeemConduit` | `conduit.createRedeemFromConduitShares()` |
| `prepareAuthorizeVehicle` | `vehicleManager.authorize()` |
| `prepareSetQueues` | `queueStrategyEngine.setQueues()` |
| `prepareSpawnMultiVehicle` | `multiVehicleFactory.spawn()` |
| `prepareSpawnAaveV3Vehicle` | `aaveV3VehicleFactory.spawn()` |
| `prepareMoveBetweenSectors` | `sectorAccountingEngine.move()` |
| `prepareDispatchVehicle` | `sectorAccountingEngine.dispatch()` |

A builder takes only what the call needs to be encoded. It takes no client, no `account` unless
the encoding depends on it, and no transaction overrides — those belong to whatever sends it.

## No approvals included

The builders emit **only** the Railnet call, and they resolve no addresses:
`prepareDepositConduit` requires `vehicle` — read it from `conduit.getVehicle()` — and
`prepareRedeemConduit` requires `outputAsset`, from `conduit.asset()`.

A deposit also needs an ERC-20 approval first, and the allowance is spent by the deposit. Send it
yourself. Redeeming needs none: the conduit burns the caller's shares internally.

The same applies to the `spawn*` builders: the factories pull an initial deposit from the caller,
so the caller must have approved the factory beforehand.

## `account` is required for deposits and redeems

`prepareDepositConduit` and `prepareRedeemConduit` take `account`, with `receiver` defaulting to it.
No other builder does.

For a deposit it is load-bearing: `conduit.create()` binds the query salt to the sender —
`query.salt` must equal `keccak256(abi.encode(msg.sender, sourceSalt))` — so the call cannot be
encoded without knowing which address will send it. Sending it from any other account reverts with
`InvalidQuerySalt`.

A redeem goes through `createRedeemFromConduitShares()`, which takes the salt raw and derives the
query salt from `msg.sender` itself, so there `account` only sets the default `receiver`.

## Salts are required, never generated

Every builder that takes a salt requires it, so a `prepare*` is a pure function of its inputs: the
same parameters always encode the same calldata. Generate them with
[`randomSalt`](/utilities/randomSalt) and keep the deployment ones — they fix the deployed address,
and `prepareSpawnMultiVehicle` takes seven at once.

```ts
import { prepareSpawnConduit, randomSalt } from '@railnetorg/railnet-sdk'

const prepared = prepareSpawnConduit({
  // ...
  querySalt: randomSalt(),
  deploymentSalt: randomSalt(),
})
```

Every builder requires its salts outright — there are no defaults. Use
[`randomSalt`](/utilities/randomSalt) per call, and log a deployment salt before you send it.
