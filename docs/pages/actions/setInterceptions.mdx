# Setting interceptions

Sets how a reward that lands on a conduit or a vehicle is routed. `initialInterceptions` sets it at
spawn; these calls replace it afterwards.

Off-chain distribution reads the rules and nothing moves on chain, so a wrong list misroutes a
reward without a revert.

## Import

```ts twoslash
import {
  assertInterceptions,
  buildSetConduitInterceptionsCall,
  buildSetVehicleInterceptionsCall,
} from '@railnetorg/railnet-sdk'
```

## The two calls

```ts
buildSetConduitInterceptionsCall({ conduit: '0x1234...', interceptions })
buildSetVehicleInterceptionsCall({ vehicle: '0x5678...', interceptions })
```

Same struct and same ceiling on both sides. The conduit call needs
`CONDUIT_SET_INTERCEPTIONS`, the vehicle call `VEHICLE_SET_INTERCEPTIONS`, each scoped to the
contract being written.

Both replace the stored list **wholesale**. An empty array clears every rule.

## Parameters

### interceptions

- **Type:** [`Interception[]`](/types/Interception)

```ts
const interceptions = [
  {
    asset: zeroAddress,                 // every asset
    recipients: [
      { target: treasury, shareBps: 7000n, chainId: 0n },   // every network
      { target: partner, shareBps: 2000n, chainId: 0n },
    ],
  },
]
```

`asset: zeroAddress` matches every asset, and a recipient's `chainId: 0n` matches every network.

Each entry's shares may sum to at most 10000 bps. A shortfall leaves the remainder undistributed;
more reverts `InterceptionSharesTooHigh`. A [fee split](/actions/buildSetFeeRecipientsCall) requires
an exact total; this is a ceiling, per entry. Two interceptions on two assets may each allocate
10000.

## assertInterceptions

```ts
assertInterceptions(interceptions)
```

The check both builders run, exported for a form to run on a draft. Throws on an entry whose shares
exceed 10000 bps, or whose `shareBps` is negative.
