# Setting interceptions

Interceptions are how a reward that lands on a conduit or a vehicle gets routed. They are settable at spawn through `initialInterceptions`, and afterwards only through these calls.

The rules are read by off-chain distribution rather than moving funds on chain, so a wrong list
misroutes a reward without reverting anything.

## Import

```ts
import {
  assertInterceptions,
  buildSetConduitInterceptionsCall,
  buildSetVehicleInterceptionsCall,
} from '@railnetorg/railnet-sdk'
```

## The two calls

```ts
buildSetConduitInterceptionsCall({ conduit: '0x1234...', interceptions })
buildSetVehicleInterceptionsCall({ vehicle: '0x5678...', interceptions })
```

Same struct and same ceiling on both sides. The conduit call needs
`CONDUIT_SET_INTERCEPTIONS`, the vehicle call `VEHICLE_SET_INTERCEPTIONS`, each scoped to the
contract being written.

Both replace the stored list **wholesale**. An empty array clears every rule.

## interceptions

- **Type:** [`Interception[]`](/types/Interception)

```ts
const interceptions = [
  {
    asset: zeroAddress,                 // every asset
    recipients: [
      { target: treasury, shareBps: 7000n, chainId: 0n },   // every network
      { target: partner, shareBps: 2000n, chainId: 0n },
    ],
  },
]
```

Two sentinels worth knowing: `asset: zeroAddress` matches **every** asset, and a recipient's
`chainId: 0n` matches **every** network.

:::warning
Each entry's shares may sum to **at most** 10000 bps — a ceiling, not an exact total as a
[fee split](/actions/buildSetFeeRecipientsCall) requires. A shortfall is legal and leaves the
remainder undistributed. Going over reverts `InterceptionSharesTooHigh`.
:::

The ceiling is per entry, not across assets: two interceptions on two different assets may each
allocate 10000.

## assertInterceptions

```ts
assertInterceptions(interceptions)
```

What both builders call, exported so a form can check a draft before a call is assembled. Throws on
an entry whose shares exceed 10000 bps.
