# buildConfigureVehicleCall

Builds the `vehicleManager.configure()` call, setting a sub-vehicle's allocation mode and its cap.

- Requires `MULTI_VEHICLE_SET_VEHICLE_AUTHORIZATION` scoped to the VehicleManager.
- Replaces the whole configuration. `mode` and `cap` are both required; there is no partial update.
- Reverts `VehicleNotAuthorized` on a vehicle never authorized, `InvalidTarget` when a finite cap
  carries `threshold > value`, and `StateUnchanged` when mode and cap already hold.

## Import

```ts twoslash
import { buildConfigureVehicleCall, VehicleMode } from '@railnetorg/railnet-sdk'
```

## Usage

```ts
import { buildConfigureVehicleCall, VehicleMode } from '@railnetorg/railnet-sdk'

const call = buildConfigureVehicleCall({
  vehicleManager,
  vehicle,
  config: {
    mode: VehicleMode.Automatic,
    cap: { value: 500n * 10n ** 18n, threshold: 10n * 10n ** 18n },
  },
})
```

## Returns

A prepared call: `{ address, abi, functionName, args }`.

## Parameters

### vehicleManager

- **Type:** `Address`

### vehicle

- **Type:** `Address`

The sub-vehicle to configure. It must already be authorized; see
[`buildAuthorizeVehicleCall`](/actions/buildAuthorizeVehicleCall).

### config

- **Type:** `VehicleConfig`

```ts
type VehicleConfig = {
  mode: VehicleMode
  cap: { value: bigint; threshold: bigint }
}
```

`VehicleMode` is `Automatic` (0) or `Manual` (1); the declaration order is the on-chain encoding.
`Manual` keeps the queue strategy from allocating into the vehicle; only an operator dispatch moves
it.

`cap.value` is in the sub-vehicle's share units (18 decimals), the units the SectorAccountingEngine
holds it in. `2n ** 256n - 1n` means unlimited; `threshold` is then ignored but stored as passed, so
send 0. `cap.threshold` is a tolerance margin in the same units and must not exceed `value` on a
finite cap.
