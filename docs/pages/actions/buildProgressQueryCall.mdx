# buildProgressQueryCall

Advances a sub-vehicle query that a dispatch left in flight. This is what
[`simulateDispatchVehicle`](/actions/buildDispatchVehicleCall) means by keeping the query to
progress it later.

The caller needs `MULTI_VEHICLE_PROGRESS_QUERY` scoped to the SubQueryEngine; the engine itself may
also drive it, so a query can progress without this call.

On an asynchronous sub-vehicle the dispatch stops short of settlement, and the proceeds do not reach
the destination sector until this runs. Watch for them with
[`getSectorBalance`](/actions/getSectorBalance).

Reverts `UnknownSubQuery` when the engine never issued this sub-query or a field does not match the
dispatch, `SubQueryAlreadyFinalized` once it is terminal, and `QueryMismatch` when `query` does not
hash to the bound id.

## Import

```ts
import { buildProgressQueryCall, toSubQuery } from '@railnetorg/railnet-sdk'
```

## Usage

Every field comes from the dispatch you sent — `queryId` is derived for you:

```ts
import { simulateContract, writeContract } from 'viem/actions'
import { buildProgressQueryCall, QueryState } from '@railnetorg/railnet-sdk'

const { request } = await simulateContract(client, {
  ...buildProgressQueryCall({
    subQueryEngine,
    chainId: base.id,
    vehicle: sourceVehicle,
    query,                                  // as simulateDispatchVehicle returned it
    settledDestination: vehicleSector(destinationVehicle),
    rejectedDestination: SECTOR_ALLOCATION,
  }),
  account,
})

await writeContract(client, request)
```

One call can chain several transitions — the engine runs its handlers as a cascade — so the state
it reaches is not necessarily the next one. Repeat until it is terminal.

## Returns

A prepared call: `{ address, abi, functionName, args }`.

## Parameters

### subQueryEngine

- **Type:** `Address`

The MultiVehicle's SubQueryEngine, from `extractMultiVehicleContracts`.

### chainId

- **Type:** `number`

Folded into the query id, which is `keccak256(abi.encode(chainId, vehicle, query))`.

### vehicle

- **Type:** `Address`

The sub-vehicle the dispatch targeted.

### query

- **Type:** `Query`

The query the dispatch created, unchanged.

### settledDestination / rejectedDestination

- **Type:** [`Sector`](/types/Sector)

Both exactly as the dispatch carried them. They are part of the sub-query's identity, so a value
that differs by one bit resolves to a different id and reverts `UnknownSubQuery` instead of
progressing the wrong thing.

## toSubQuery

```ts
const subQuery = toSubQuery(parameters)
// { vehicle, queryId, settledDestination, rejectedDestination }
```

The struct the builder assembles, exported for anyone who needs it alone — to compute a sub-query id
off chain, or to compare against an event.
